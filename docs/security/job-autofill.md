# Job posting autofill

The Add application form uses one `JobListingExtractor` for both URL and HTML parsing. Primary coverage is LinkedIn guest markup, JobStreet/SEEK detail state and data-automation markup, Glints Next.js detail payloads, and JobPosting JSON-LD. Kalibrr/Dealls Next.js detail data and Talentics Vue job/organization data are retained as secondary paths. Synthetic fixtures represent the supported payload shapes; they are not a guarantee that every current portal page exposes those shapes.

Extraction prioritizes explicit JobPosting data, known detail-page state, and scoped page elements, before conservative title/meta fallbacks. Related-job queries are excluded. Multiple JobPosting blocks are matched by URL or the page heading rather than blindly choosing the first. Company names are never filled from a portal domain/site name, and an employer is never copied into location. Unknown employment types remain empty. Descriptions preserve nested paragraphs/lists up to 12,000 characters. Multiple locations and explicit remote/hybrid arrangements are retained in the response and source notes.

The form fills only empty fields, including employment type and source description in Notes. Existing data and changes typed while fetching are preserved. Responses for changed URLs or detached forms are ignored. Duplicate clicks share one pending operation. Partial extraction identifies missing fields instead of claiming a complete import. Source location and work mode are retained in Notes, including when the structured province/city control cannot represent them. Jakarta alone chooses DKI Jakarta without inventing Jakarta Selatan; explicit city names use boundary-aware matching, and ambiguous/multiple locations need manual selection.

Requests use the existing pinned, allowlisted `JobPageFetcher`. If a page is unreadable and an authenticated internal renderer is configured, the same guarded `ScraperPageFetcher` can recover rendered content. No public third-party CORS proxy is used. URL validation failures do not fall through to another fetcher. No headless renderer was installed, started, or configured during this change. Login-only, blocked, expired, and structurally changed portal pages may still need manual entry or the browser extension. No AI extraction or extra provider cost was introduced.

Regression fixtures cover structured data, referenced organizations, multiple locations, guest markup, hydration detail state, related-job exclusion, employment-type mapping, nested descriptions, blank/blocked pages, guarded transport, renderer recovery, manual edit preservation, and stale responses. Tests do not log into job portals or use private applicant data. Validate representative live job URLs in staging and add sanitized fixtures when a portal changes markup.

Additional Dealls/Talentics/Kalibrr coverage includes nested query detail envelopes (`data.job`), duplicate detail payload deduplication, quoted Vue keys, organization names, employment type aliases, separate requirements/qualifications fields, and explicit remote/hybrid work arrangements. Tests use sanitized synthetic payloads and preserve the same URL allowlist and guarded transports. These adapter paths still need representative live-page checks when portal markup changes; no authenticated portal session was used.
