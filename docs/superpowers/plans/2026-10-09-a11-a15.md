AI queue uses a dedicated asynchronous database connection (`ai_photos`) with retry-after 360 seconds and worker timeout 330 seconds, above the 300-second provider timeout. Failed processing is not automatically sent to the provider again: a provider timeout can be ambiguous, so retries require an explicit new attempt. A recovery command refunds abandoned processing once and redispatches queued records. Legacy photo records default to completed.
